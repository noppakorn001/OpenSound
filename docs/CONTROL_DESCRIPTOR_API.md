# Control descriptor API

`control-descriptors.json` is generated from pinned public protocol declarations, with metadata provenance. It is a backend input, not a raw-packet editor or permission to send commands. The compact `feature-catalog-ui.json` provides English titles, groups and honest status/reason strings; the app should use these summaries rather than display source offsets or opcodes.

A descriptor identifies `protocol` (`v1t1`, `v1t2`, `v2t1`, `v2t2`), frame family, inquiry, SET opcode, possible RET counterpart, fields, packet size, and category. Each field has an offset, width, English title, choice options when its declared enum is known, and a reference default. Reference defaults do not represent the connected device's settings. Fields with numeric ranges or nested structures require device capability bounds or explicit codecs before becoming editable.

All descriptors start disabled. A backend enables one only after an explicitly reviewed advertised-function binding, supported table, successful current readback, availability reply, exact packet size, valid enum values, and device capabilities. Preserve every untouched byte from the confirmed current state. Do not fill a missing state from reference defaults. After SET, require a matching decoded RET/notification and settled state before reporting success. An ACK alone is insufficient.

`fixed_layout` establishes that the reference declares fixed/generated serialization and all visible fields have known widths. It does not establish an audited Sony packet layout. `exact_readback_layout` compares the declared SET fields with a named RET counterpart. Custom/variable serialization, arrays, strings, assignments, pairing lists and asset transfers require dedicated typed handlers. Never derive model-specific function-to-inquiry mappings by using a low nibble or matching names approximately.

Firmware-updater descriptors are excluded from application controls. Phone/service dependencies need a supported macOS implementation. A support capability only establishes that a device advertises the function; it does not establish that a host can implement the complete product feature.

Public builds and catalogue tests require only the shipped JSON files. The reference checkout is optional and is not included in the public archive. For regeneration, retrieve the MIT repository `https://github.com/mos9527/SonyHeadphonesClient` into `tests/reference/SonyHeadphonesClient` and check out commit `f11d686332e9aaf7630f9fb8a104b70c5d6f342c`.

Rebuild all outputs with `python3 scripts/generate-feature-catalog.py`; verify them with `python3 scripts/generate-feature-catalog.py --check`. Run `python3 tests/FeatureCatalogTests.py` independently; it checks the shipped inventory and descriptors and adds a regeneration check only when the pinned reference checkout is present. The input is `tests/reference/SonyHeadphonesClient` at the pinned commit and `docs/ipa-protocol-provenance.json`. The latter contains compact protocol names and method addresses, never extracted binary or image bytes. Remove it only if deliberately regenerating a source-only inventory with `--ipa-anchors` pointing to an absent path.
